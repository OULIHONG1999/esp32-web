# 字体云端服务架构方案（替代 FontBox SoftAP 直连）

> 本文件是**已确认的设计原文挂载**，供人与 AI 通过站点直接阅读。
> 配套：[`protocol.md`](./protocol.md) 为本站已实现的 API 契约；仓库内 `server.py` / `public/` 为腿 A 本地原型。

## 智能体速读

1. **这篇讲什么**：把字体供给从「SoftAP 直连推送」改为「云端做子集化、设备端按需拉取、本地缓存显示」的新架构设计。
2. **什么时候读**：动手实现云端服务、设备端 font 拉取客户端、清理旧 FontBox 方案之前，全文必读。
3. **阅读模式**：§1–§4（定位 / 决策 / 架构 / 数据流）全文必读；§5–§7（API / 缓存 / 清理）按需精读对应小节；§8 附录仅参考。
4. **最容易踩的点**：见 §6「缓存策略」——设备端不引入缓存 key/哈希；固定文本走构建期子集化预置，云端只负责动态文本增量字；动态文本（歌词/便签/小说）按「字」缓存、单文件合并、不按字号分文件（同字体多字号共享字形源）。

## 1. 一句话定位

放弃 SoftAP 直连（旧 FontBox：手机/PC 就近把「文本 + 子集字体」推到设备）。改为云端集中子集化，设备作 WiFi STA 主动向云端 API 索取所需字的字体数据，落到本地 LittleFS 缓存后交给 LVGL 渲染。

一句话：**固定文本离线预置，动态文本按需拉字，云端只做「给字」这一件事。**

## 2. 关键决策（已与用户确认，勿再返工）

| 维度 | 决策 | 依据 / 说明 |
|------|------|-------------|
| 联网方式 | 设备作 WiFi STA，连现有 WiFi | 芯片自带 WiFi；4G 模块属未来扩展，不在本期 |
| 云端形态 | 自建服务器 + 域名，提供 HTTP API | 不是第三方字体 CDN |
| 字体来源 | 云端存多个字体库；管理员可上传自定义字体（预留方向）；部署时预置几个默认字体 | — |
| 子集化位置 | 云端（fontTools pyftsubset 或等价） | 设备端零子集化负担 |
| 固定文本 | = 界面写死的字符串（标题/菜单/按钮/提示），字集编译期完全确定 | 走构建期本地子集化 + 预置，开机零联网可用 |
| 动态文本 | 运行时拉取后显示的内容，字集不可预知 | 来源暂不确定，走云端按需增量拉字 |
| 缓存同步时机 | 纯按需，不主动同步、不后台预取 | 逻辑最简，零背景流量；首显冷僻字有网络延迟，接受 |
| 缓存 key | 不需要独立 key，文件名即标识 | 设备发起请求时已知自己要哪个字 |
| 缓存配额 | 先不定组织方式，先把配额留出来 | 11MB LittleFS 里预留 fonts 子目录专用配额 |

## 3. 总体架构

```
                 ┌─────────────────────────────────────────────┐
                 │            云端（自建服务器 + 域名）          │
                 │                                             │
                 │  字体库存储（多个 TTF/OTF，管理员可上传）       │
                 │        │                                     │
                 │        ▼                                     │
                 │  fontTools 子集化服务（按请求字符即时/预生成）   │
                 │        │                                     │
                 │        ▼                                     │
                 │  HTTP API  /subset?font=&chars=...           │
                 └─────────────────────────────────────────────┘
                                  ▲  │
                    WiFi（设备作 STA） │  └── 返回子集 TTF/位图数据
                                  │  ▼
                 ┌─────────────────────────────────────────────┐
                 │              设备端（ESP32-S3）               │
                 │                                             │
                 │  字体管理器（font service）                    │
                 │   ├─ 固定文本：启动加载预置子集（离线）          │
                 │   ├─ 动态文本：缺字 → 请求云端 → 写缓存         │
                 │   └─ 本地缓存索引（文件名即 key）               │
                 │        │                                     │
                 │        ▼                                     │
                 │  LittleFS /fs/fonts/（缓存目录）               │
                 │        │                                     │
                 │        ▼                                     │
                 │  lv_tiny_ttf 渲染                            │
                 └─────────────────────────────────────────────┘
```

### 3.1 两条供给路径（对应「固定 vs 动态」分类）

- **固定文本路径（离线，构建期）**：发布时收集界面所有字符串 → 本地 pyftsubset 子集化 → 产物打进固件或预置 LittleFS → 设备开机即可显示，不依赖联网。
- **动态文本路径（在线，运行时）**：需要显示的字若本地缓存没有 → 请求云端 `/subset` → 拿到子集数据 → 写 LittleFS 缓存 → 渲染。

两条路径对 LVGL 完全透明：最终都落到一个 `lv_font_t *` 交给 label。

## 4. 数据流（动态文本按需拉字）

```
设备要显示动态文本（如一段歌词）"天青色等烟雨而我在等你"
   │
   │  ① 字体管理器对文本去重 → {天,青,色,等,烟,雨,而,我,在,你}
   │  ② 比对内存索引，缺字 {青,烟,雨}（其余已缓存）
   │
   │  ③ 缺字 → GET/POST /subset?font=msyh&chars=青烟雨
   │     （整段缺字一次性请求；不带 px，字号属设备端渲染维度）
   │
   │  ④ 云端：fontTools 即时子集化 → 返回子集 TTF 字节
   │
   │  ⑤ 设备：写入 /fs/fonts/ 缓存
   │        更新内存索引表「已缓存字符集」
   │
   │  ⑥ lv_tiny_ttf 加载（create_file / create_data，按字号建实例）→ label 渲染
   ▼
显示完成；下次同字命中本地缓存，零网络请求
```

## 5. 云端 API 设计（草案）

| 端点 | 方法 | 用途 | 关键参数 | 返回 |
|------|------|------|----------|------|
| `/fonts` | GET | 列出可用字体库 | — | JSON：[{id, name, family, ...}] |
| `/subset` | GET/POST | 按需子集化 | font（字体 id）、chars（待子集字符） | 子集字体二进制（TTF） |
| `/upload` | POST | 管理员上传自定义字体 | 鉴权 + 字体文件 | 字体 id（预留） |
| `/meta` | GET | 版本/能力协商 | — | JSON：协议版本、支持的输出格式等 |

### 5.1 关键设计点

- **输出格式**：返回 TTF 子集（复用现有 lv_tiny_ttf 能力，任意字号，一条路走通固定/动态两类文本）。位图格式属后续优化项，不阻塞本期。
- **子集化粒度**：按请求 chars 即时子集化（字集随内容漂移无法预生成）。
- **协议复杂度克制**：响应头/查询串优先用简单文本；`/fonts` 列表这类结构数据可 JSON。
- **鉴权**：本期先按「内网/自用」假设，不设计复杂鉴权。

云端服务独立成篇：云端侧完整设计见 `docs/font-cloud-server.md`（可脱离设备端单独开发验证）。

## 6. 缓存策略（核心）

### 6.1 为什么不需要独立 key

设备端是主动拉取模型：设备发起 `/subset?font=msyh&chars=张` 时，天然知道自己要的是「msyh 字体的『张』字」。云端返回的数据就对应这个已知实体。

- 文件名直接编码身份（或以 `font + sorted(unique chars)` 为缓存键）。
- 命中判断 = 「该文件是否存在」/ 索引命中。
- 不需要「云端分配整包 ID」——设备永远是请求发起方，不存在「被动收到不知内容的包」。

### 6.2 已确定部分

- 存储位置：LittleFS `/fs/fonts/` 子目录，专用。
- 写方式：tmp + rename 原子写（掉电安全）。
- 同步时机：纯按需，无启动全量同步、无后台预取。
- 配额：11MB LittleFS 中为 `/fs/fonts/` 预留固定配额（见 §6.8）。

### 6.4 配额与 LittleFS 约束

- 当前分区目标：factory(app) 4M + storage(littlefs) 11M（以实现时分区表为准）。
- 固定文本预置字体占用的是构建期产物，与动态缓存分开计量。
- 动态字缓存配额建议先按 **2MB** 预留。

### 6.5 使用场景（驱动后续决策）

动态文本典型场景：**动态歌词、便签文本、小说内容**。共同特征：

1. 文本流：一段一段进来，非固定界面文案。
2. 字集稀疏且随内容漂移：每段几十~上千字；长期趋近常用字全集。
3. 同一字体、任意字号：必须保留 TTF 任意缩放能力。
4. 核心诉求：不装完整字体库，只存「实际出现过的字」。

### 6.6 待定项收敛结果（已拍板）

| 待定项 | 收敛结论 | 理由 |
|--------|----------|------|
| 一次性拉几个字 | 按「整段文本」批量拉 | 歌词/便签/小说都是整段到达；逐字请求网络开销大 |
| 子集化粒度 | 按请求 chars 即时子集化 | 字集随内容漂移，无法预生成 |
| 缓存文件组织 | 按字体累积 + 索引记录已有字 | 「按字缓存 + 任意字号」约束下的最优解方向 |
| 配额数值 | 2MB（LRU 淘汰） | 见 §6.8 |

### 6.7 缓存文件组织

因为「同字体多字号共享字形源」，**不能**按 `<font_id>_<px>_<chars>.subset`（带字号）组织——同一字 16px/28px 会重复缓存。

```
/fs/fonts/
  msyh.subset      ← 一个字体一份累积子集（不含字号维度）
  index.dat        ← 持久化字集索引（重启后知道已有哪些字）
```

- 内存索引表：运行时维护 `{ font_id → 已缓存字符集 }`，命中判断查内存索引。
- 拉取流程：文本去重 → 比对索引 → 缺字集合 → 一次请求 → 写缓存 → 更新索引。
- 渲染：同一份 TTF 数据/文件创建**多个字号实例**（勿用 `lv_tiny_ttf_set_size()` 高频轮换——会清空字形缓存）。

> **实现注意（评估结论）**：TrueType 不可字节追加合并。「单文件 append」在设备端不可行。可选路径：A) 云端按「已有字∪新字」全量重生成后整文件替换；B) 多分块 + 字形路由；C) 块数超阈值后云端重建。原型（本仓库）采用服务端缓存键 + 整文件返回，设备端落盘策略实现时在 A/C 中择一。

### 6.8 容量与淘汰

- 单字开销：中文字形子集化后约 **100–200 B/字**（实测 200 常用字 ≈ 150 B/字）。
- 3500 常用字 ≈ 0.5–0.7 MB；GB2312 全 6763 字 ≈ 1–1.5 MB。
- **2MB** 配额足以容纳「一套字体 + 数千字」。
- 淘汰（LRU）：逼近上限时按整文件重建（保留最近使用 N 字，云端回一份精简子集更现实）。
- 多套字体：每套一份累积文件，共享总 2MB。

## 10. 本地原型补充（本仓库实现与方案的差异点）

| 点 | 方案 | 本原型 |
|----|------|--------|
| `/subset` 传参 | GET 查询串 | **支持 POST JSON**（避开 URL 长度限制；GET 仍保留便于调试） |
| 缓存键 | 文件名编码 chars | `sha1(font + sorted(unique chars))`，与顺序无关 |
| px | 已拍板不带 | 接口刻意不接受 px |
| 统计 | 未要求 | `/api/stats` + 测试台图表（命中率/延迟/体积/历史） |
| 文档挂载 | 分散 md | 本目录 `architecture.md` + `protocol.md`，站点 `/docs/` 可直达 |
