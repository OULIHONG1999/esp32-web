AI 速读 · 本页是什么

机器可读描述符 /ota.json

本页是 OTA 设备下发台：从云端看到当前在线/曾在线设备，选中设备 + 选中固件版本， 下发一条 OTA 命令；设备在下次心跳（report）时把命令取走并自升级。 页面数据全部来自服务器实时接口（无本地假数据），每 5 秒轮询一次。

三个接口（契约详见 /docs/ota.md §4）

  • GET /api/devices设备列表，公开只读
  • GET /api/registry固件版本列表，公开只读
  • POST /api/devices/{deviceId}/commands下发 OTA · 需 Bearer token
  • POST /api/devices/{deviceId}/report设备上报 · 免鉴权（设备端职责）
  • POST /api/devices/{deviceId}/commands/{id}/result设备回执 · 免鉴权（设备端职责）

命名与约定

deviceId
base MAC，去冒号小写十六进制，如 3485a1b2c3d4

pending → delivered → success / failed
在线判定

app 段 sha256（复用 registry）
通信模型
HTTP 轮询 pull，非推送

下发 OTA 命令

POST /api/devices/{deviceId}/commands

设一次就长期有效——本机记住，下次打开不用再填（与主站共用同一个 fw.token，在主站 🔑 设过这里自动就有）。
换浏览器 / 清了浏览器数据：点「🔗 复制设置链接」存成书签，需要时打开该链接即自动写入。Token 放在 # 片段里（不发给服务器、不进日志、不留 Referer）。
要新 token：打开 主站首页 → 右上角 🔑 → 生成（需输入主 token）；或直接粘贴别人给你的 wk_ 工作 token。

命令生命周期：pending 已入队 → delivered 设备已取走 → success / failed 回执。 每个设备至多一条未决命令：已有未回执命令时再下发返回 409，勾选上方「顶替未决命令」可强制顶替。 设备取走后若没回执（如中途断电），下次上报服务器会重复投递同一条。

OTA 过程

选中设备：未选设备 · 每 5s 刷新

过程点来自设备端的进度上报（POST /api/devices/{id}/commands/{cid}/progress，免鉴权）。 设备端没实现也照常可用——那时只能看到服务器可见的时间点（下发 / 取走 / 回执）。 设备侧接入方法见 /docs/DEVICE-OTA.md §4.5（契约）+ §7.8（ESP-IDF 骨架）。
