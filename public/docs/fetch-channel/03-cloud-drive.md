## 1. 背景与目标

fetch 通道（[`README.md`](README.md) / [`02-server.md`](02-server.md)）解决了"命令设备下载"，但它需要一个**文件源**。v1 用服务器上一个静态目录凑合；云盘把它升级成正式能力：

| 目标 | 说明 |
|---|---|
| 存 | 宿主机 / 智能体把任意文件（JSON、字体、音频、图片、文档…）上传到云端留存 |
| 取 | 设备经 fetch 命令下载安装到 `/fs` 或 `/sdcard`；智能体 / 人经 HTTP 直接下载查看 |
| 管 | 列表、元数据（大小 / 上传时间 / 备注）、删除 |

一句话：**给这套"设备 + 智能体 + 人"的协作体系一个共享文件仓库。**

## 2. 用户故事

1. 智能体写好一份 vanim 动画 JSON → 上传云盘 → 下发 fetch 命令 → 设备 15 s 后开始播放新动画。全程无 USB、无重刷。
2. 用户在设备上录了一段音频（未来）→ 智能体从云盘取回分析。
3. 智能体生成一份报告 / 截图 → 传云盘 → 用户手机浏览器打开链接查看。
4. 固件发布的字体子集文件放云盘 → 下发 fetch 装进 `/fs/fonts/`。

## 3. 功能需求（v1）

| 编号 | 需求 | 优先级 |
|---|---|---|
| F1 | 上传文件（二进制，≤ 单文件上限），返回 `fileId` 与下载 URL | P0 |
| F2 | 列出全部文件（分页可选）：`fileId`、展示名、大小、上传时间、备注 | P0 |
| F3 | 下载文件原始字节（给设备 / 智能体） | P0 |
| F4 | 删除文件 | P0 |
| F5 | 单文件元数据查询（`?meta=1`） | P1 |
| F6 | 重命名 / 更新备注 | P2 |
| F7 | 简单网页浏览/上传界面 | P2（可后置） |

**v1 非目标**：多用户/多租户、目录层级（扁平存储）、版本历史、断点续传、秒传/去重、分享链接权限、客户端同步。

## 4. API 草案

> 命名风格对齐现有服务器（camelCase、`/api/` 前缀、token 鉴权同 publish）。

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/drive/files` | `POST` | 上传。`multipart/form-data`（字段 `file` + 可选 `note`），或原始 body + `X-Filename` 头。返回 `{ fileId, url, size, name, createdAt }` |
| `/api/drive/files` | `GET` | 列表 `{ files: [ { fileId, name, size, note, createdAt, url } ] }` |
| `/api/drive/files/{fileId}` | `GET` | 下载原始字节（设备 / 智能体用）；`?meta=1` 返回元数据 JSON |
| `/api/drive/files/{fileId}` | `DELETE` | 删除（含磁盘文件与元数据） |

* 下载 URL 稳定：`http://175.178.156.231/api/drive/files/{fileId}`——**fetch 命令的 `url` 直接填它**。
* `Content-Type`：按上传时的 MIME / 扩展名返回；未知给 `application/octet-stream`。
* 错误风格沿用现有 API（4xx + `{"error": "..."}`）。

## 5. 存储与限额

| 项 | 建议值 | 说明 |
|---|---|---|
| 磁盘布局 | `data/drive/<fileId>` 平坦文件 + `data/drive/index.json`（或 sqlite）元数据 | `fileId` 服务端生成（如 `f_` + 随机/时间戳），**与用户文件名解耦** |
| 单文件上限 | **8 MB** | 设备经 fetch 下载受 4 MB 顶；更大文件面向智能体/人 |
| 总配额 | 1 GB（可配） | 超额：上传返回 **413**；可配 LRU 清理（v2） |
| 文件名净化 | 展示名去路径分隔符、控制字符；存储只用 `fileId` | 防 `../` 与编码问题 |
| 删除 | 磁盘 + 元数据一起删；幂等（重复 DELETE → 200） | |

## 6. 安全

* **写操作（上传/删除）**：沿用 publish token（`Authorization: Bearer`）。
* **读操作（列表/下载）**：默认**开放**（设备端 `net::http_get` 不带 token，设备要下载就不能要求鉴权）。若需私密文件，v2 加"带过期时间的签名 URL"。
* 上传内容**不做病毒/内容审查**（内网工具属性）；但响应头不要开 `Content-Disposition: inline` 以外的东西让浏览器误执行——HTML/SVG 文件建议强制 `Content-Disposition: attachment` 或改后缀。

## 7. 与 fetch 通道的关系（对齐点）

云盘是 fetch 的**推荐文件源**，两者通过一个 URL 字段衔接，无其他耦合：

```
智能体 ──POST /api/drive/files──► 云盘（返回 url）
智能体 ──POST /api/devices/{id}/commands {type:"fetch", url, dest}──► 命令通道
设备  ──GET url──► 云盘 ──字节──► 设备落盘 /fs 或 /sdcard
```

* 设备侧约束（fetch 契约）：`url` 必须完整 `http://`；文件 ≤ `maxBytes`（≤4 MB）；目标路径白名单 `/fs/`、`/sdcard/`。云盘 **不需要**知道 dest，也不解析文件内容。
* 静态目录（02 §5 的 `/files/`）与云盘并存即可；云盘稳定后 `/files/` 可退役。

## 8. 验收清单（草案）

1. 上传 100 KB JSON → 返回 fileId；curl 下载字节一致（md5 对得上）。
2. 上传 9 MB 文件 → 413。
3. 列表含新文件，字段齐全；删除后列表消失、再 GET 下载 → 404。
4. 设备端到端：fetch 命令 `url=云盘 URL`，`dest=/fs/vanim/test.json` → 15 s 内回执 success，设备页可见可播。
5. 展示名含中文/空格/`../` → 上传成功且存储名安全，列表展示名正确。

## 9. 开放问题（需求方拍板）

| # | 事项 | 倾向 |
|---|---|---|
| 1 | 读是否要求鉴权 | 开放（设备要无凭据下载） |
| 2 | 元数据存储 | JSON 文件起步，量大了换 sqlite |
| 3 | 是否要"按项目/标签分组" | v1 扁平 + `note` 字段 |
| 4 | 过期策略（自动清理 N 天前文件） | 不自动清，手动管理 |
| 5 | 上传端鉴权失败的错误码风格 | 与现有 API 一致（401） |
