# F3: 第三方/社区 Web 烧录方案与替代通道

## Findings

### [1] 浏览器直连烧录的公开生态高度收敛于 esptool-js 内核：npm 搜索显示主流候选仅 esp-web-tools（v10.4.0，月下载约 2.5 万）与官方 esptool-js，未发现与之竞争的成熟独立 Web 烧录库
- quote: "esp-web-tools | Web tools for ESP devices | version 10.4.0 | date 2026-07-15"
- url: https://registry.npmjs.org/-/v1/search?text=esp32%20flash%20web%20serial&size=10
- source_type: secondary (npm registry)
- published: 2026-09-26 (查询)
- confidence: medium
- note: 搜索结果为相关度排序，存在漏检可能

### [2] esptool-js 官方 demo 新增了 WebUSB (CH340/CH341) 实验通道（v0.7.0 changelog 记录 WebUSBSerialPort 改进，PR #265），动机是桌面 OS 的 usbserial 内核驱动常占用 CH340 导致 Web Serial claimInterface 失败；Android Chrome OTG 是更可靠的 WebUSB 场景
- quote: "Documented bug fixes including ... WebUSBSerialPort improvements for CH340"
- url: https://api.github.com/repos/espressif/esptool-js/issues?state=all&per_page=20&sort=updated (PR #271 body)
- source_type: primary
- published: 2026-09-21
- confidence: high

### [3] WebUSB 不是 Web Serial 的平替：WebUSB 访问的是未被 OS 驱动 claim 的原始 USB 设备，而多数开发板的 USB-UART 桥（CP210x/CH340/FTDI）在桌面系统上已被内核驱动占用；仅当芯片自带 USB-JTAG/Serial 复合设备（如 ESP32-S3/C3 原生 USB）时 WebUSB 才有意义
- quote: "WebUSB API — which provides raw access to USB devices that have not been claimed by an OS driver"
- url: https://developer.mozilla.org/en-US/docs/Web/API/Web_Serial_API
- source_type: primary
- published: 2026-05-26
- confidence: medium (综合推断: [speculative] 关于"仅原生 USB 芯片有意义"的结论)

### [4] 作为"网页端更新"替代品的 OTA 是另一条路线：esp_https_ota 是设备端（ESP-IDF 内）通过 HTTPS 拉取固件升级的抽象层，支持服务器证书校验、分段下载（partial_http_download）、断点续传（ota_resumption）、镜像签名验证与预加密固件，但它要求设备已联网且已运行可升级的应用——不能替代浏览器串口烧录来"救砖"或首次刷机
- quote: "esp_https_ota provides simplified APIs to perform firmware upgrades over HTTPS. It is an abstraction layer over the existing OTA APIs."
- url: https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/system/esp_https_ota.html
- source_type: primary
- published: ESP-IDF v6.1 (2026)
- confidence: high

### [5] ESP RainMaker 是乐鑫的端到端云方案（Claiming + Agent + Cloud + App），其 README 直接提供 "Try it with ESP Launchpad" 入口——即乐鑫把"网页串口首刷（Launchpad）"与"云 OTA（RainMaker）"组合为完整交付链路
- quote: "ESP RainMaker is an end-to-end solution offered by Espressif... [Try it with ESP Launchpad]"
- url: https://raw.githubusercontent.com/espressif/esp-rainmaker/master/README.md
- source_type: primary
- published: 2026 (branch master)
- confidence: high

### [6] 第三方 Web 方案的实质格局：esp-web-tools（ESPHome/OHF 出品）是唯一被广泛采用的非乐鑫封装层，它与乐鑫 ESP Launchpad 都构建在 esptool-js 之上；ESP Web Tools 额外提供 Improv Wi-Fi 配网、设备 Web 控制台、Home Assistant 接入等烧录后生态功能
- quote: "ESP Web Tools is a project by ESPHome, Open Home Foundation. Development is funded by Nabu Casa."
- url: https://esphome.github.io/esp-web-tools/
- source_type: primary
- published: 2026
- confidence: high

## Dead ends
- espressif/esp-web-flasher 仓库不存在（main/master 分支 README 均 404）——该名字不可用作候选
- DuckDuckGo/Bing 搜索接口 transport error，无法枚举长尾社区 Web 烧录器
- Arduino Web Editor / Arduino Cloud 的浏览器上传机制文档多次 fetch 失败（docs.arduino.cc 404、support.arduino.cc transport error），未能核实其是否已用 Web Serial，列为未决
- PlatformIO 未找到浏览器端烧录能力的一手证据，暂按"本地 CLI 工具链"理解，[unverified]
- api.github.com 搜索接口时通时断（repositor search transport error，issues 接口成功）

## Suggested follow-ups
- Arduino IDE for Web / Arduino Cloud 当前上传链路是否已基于 Web Serial（对用户做"非乐鑫生态浏览器烧录"对比时有价值）
- WebUSB 直连 ESP32-S3/C3 原生 USB-JTAG 的可行性与 esptool-js WebUSBSerialPort 的实际成熟度
- 企业内网自签名 HTTPS 环境下 Web Serial 的可用性（secure context 是否接受自签证书）
