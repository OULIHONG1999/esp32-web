# FETCH 命令通道 —— 让设备下载任意文件到指定位置（交接文档包）

> **【智能体速读】**
>
> * **这篇讲什么**：`fetch` 命令通道的**交接文档包**。目标：通过现有云端命令通道，下发一条命令让设备从任意 HTTP 源下载一个文件，存到**内置 flash（`/fs/`）或 TF 卡（`/sdcard/`）**的指定路径——目录不存在就逐级创建，同名文件直接覆盖。
> * **什么情况读**：① 服务器端实现（把本包交给服务器智能体）→ 先读本文 §3 契约，再**全文必读** [`02-server.md`](02-server.md)；② 设备端固件实现 → **全文必读** [`01-device.md`](01-device.md)；③ 云盘新项目 → [`03-cloud-drive.md`](03-cloud-drive.md)。
> * **阅读模式**：本文 `按需查 §3`（契约单一事实来源）+ `§5`（注意事项）；三份分册各有自己的阅读模式。
> * **关键小节**：**§3 双方对齐契约**（设备端与服务器端都以此为准，**禁止各自另写一份**）；§6 实施顺序。
> * **最容易踩的点**：① **先探测再动手**——服务器当前只见过 `type:"ota"`，是否放行其他 type 未知（见 02 §0）；② 设备**在线窗口仅 45 s**、每设备**至多一条未决命令**；③ `dest` 白名单只有 `/fs/` 与 `/sdcard/` 两棵子树，其余一律拒绝。

***

## 1. 背景与要解决的问题

设备端文件（vanim 动画 JSON、字体、音频、表情数据等）目前只能靠**构建期预置**进 `storage.bin`（LittleFS 分区镜像）。但发布链路的 OTA（`esp_ota_ops`）**只写 app 槽，不写 storage 分区**——2026-10-16 实测：发布包含 storage 段，OTA 后设备上依然没有 `/fs/vanim/` 预置。

也就是说：**改一个数据文件 ≠ 要重刷/重发固件**。需要一个轻量通道：

```
宿主机 CLI ──► 固件服务器（命令通道，已有）──► 设备（每 15 s 轮询）
                                                    │
                                    GET url（任意 HTTP 源，PSRAM 缓存）
                                                    │
                                    写 /fs/... 或 /sdcard/...（建目录、覆盖）
                                                    │
                              POST result（success/failed + 原因）──► CLI 收回执
```

vanim 播放页（`pages/vanim`）里已有一个雏形：FETCH 按钮从固定 URL 下载到固定路径 `/fs/vanim/fetched.json`。本方案把它**泛化成一条服务器命令**：URL 与目标路径都由命令携带。

## 2. 方案一句话

**在现有 OTA 命令通道上新增一种命令类型 `fetch`，载荷只多三个字段（`url` / `dest` / `maxBytes`）；设备端由 OTA agent 的轮询循环代收，转交新的 `fetcher` 组件执行；回执复用现有 result 端点。** 服务器端、宿主机 CLI、设备端三方都不新建通道。

## 3. 双方对齐契约（单一事实来源）

> 设备端文档（01）与服务器端文档（02）的接口描述**都以本节为准**。改契约先改这里，再同步两侧。

### 3.1 下发命令

`POST /api/devices/{deviceId}/commands`

```json
{
  "type": "fetch",
  "url": "http://175.178.156.231/files/vanim/robot.json",
  "dest": "/fs/vanim/robot.json",
  "maxBytes": 262144
}
```

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `type` | string | 是 | 固定 `"fetch"` |
| `url` | string | 是 | **完整绝对 URL**，仅 `http://`（设备端 `net::http_get` 只支持明文 HTTP）；长度 ≤ 256 |
| `dest` | string | 是 | 设备侧目标**绝对路径**；**必须以 `/fs/` 或 `/sdcard/` 开头**；只允许 ASCII 可打印字符；禁止 `..`；总长 ≤ 127 |
| `maxBytes` | int | 否 | 下载大小上限，字节；缺省 262144（256 KB），允许范围 1..4194304（4 MB），越界取边界 |

### 3.2 命令信封（report 响应携带）

服务器在下一次 `POST /api/devices/{deviceId}/report` 的响应里返回完整命令体：

```json
{
  "now": "2026-10-16T08:00:00Z",
  "command": {
    "id": "cmd_a1b2c3",
    "type": "fetch",
    "url": "http://175.178.156.231/files/vanim/robot.json",
    "dest": "/fs/vanim/robot.json",
    "maxBytes": 262144,
    "createdAt": "2026-10-16T07:59:00Z"
  }
}
```

设备端**只认信封里这六个字段**；服务器不得依赖其他字段传递语义。

### 3.3 回执

`POST /api/devices/{deviceId}/commands/{commandId}/result`（**端点不变**）

```json
{ "state": "success", "detail": "wrote 11234 bytes to /fs/vanim/robot.json" }
```

```json
{ "state": "failed", "detail": "bad dest: must start with /fs/ or /sdcard/" }
```

* `detail` 一律 **ASCII**（≤ 120 字节），错误码表见 [`01-device.md`](01-device.md) §4。
* 失败**不重试**：设备不会自己重试同一条命令；要重试就由宿主机重新下发（同参数即同效果，覆盖语义）。

### 3.4 状态机与重投（全部沿用现有语义）

| 机制 | 行为 |
|---|---|
| 每设备未决命令 | 至多一条（现有规则）；下发时已有未决 → **409**，宿主机可选择 `--force` 顶替（旧命令标 `superseded`） |
| 设备离线 | **412，命令不入队**（现有规则）；设备上线后由宿主机重跑 |
| 未回执重投 | 服务器会把未收到回执的命令再次投递；对 fetch **无害**——重复执行就是重复覆盖同一份内容，**天然幂等** |
| 断电恢复 | 设备端结果有 NVS 暂存重发机制（OTA 已有）；fetch 执行中断电最多残留一个 `dest.tmp` 孤儿文件，下次执行同 dest 时顺带清理 |

### 3.5 执行顺序保证

服务器**保证同一设备的命令串行投递**（一条未决机制已天然保证）；设备端一次只执行一条 fetch；fetch 与 OTA 不并发（OTA 进行中收到 fetch → 直接回 `failed: busy`）。

## 5. 注意事项（三端都看）

1. **在线窗口 45 s**：服务器以 `now - lastSeen > 45 s` 判离线；下发前用 `node scripts/list-devices/list-devices.js` 确认在线。
2. **命令是拉不是推**：设备每 15 s report 一次，命令送达有 0~15 s 延迟，属正常。
3. **安全边界**：fetch 能写设备的两个文件系统，因此 `dest` 白名单、路径校验、大小上限在**设备端和服务器端各做一遍**（纵深防御）；服务器端校验不是可选项。
4. **仅明文 HTTP**：`net::http_get` 走明文 HTTP（与 OTA/fontnet 一致）；HTTPS 需先给 net 层加证书支持，不在本期。
5. **`/fs` 容量 ≈ 9.9 MB**（`storage` 分区 `0x9DE000` @ `0x622000`，见 `docs/filesystem.md`）；`/sdcard` 容量随卡。设备端下载前会查剩余空间。
6. **本包是设计契约**，两侧尚未编码；落地后请回填「已实现」标记。

## 6. 实施顺序

| 步骤 | 谁 | 内容 | 依赖 |
|---|---|---|---|
| 0 | 服务器端 | **探测**：POST 一条 `type:"fetch"` 命令，观察是否被接受/透传（02 §0） | 无 |
| 1 | 服务器端 | 命令通道放行 + 校验 + 透传 fetch；静态文件托管（02 §3–§5） | 步骤 0 结论 |
| 2 | 设备端 | `components/fetcher/` + ota.cpp 分发；编译、发布 | 无（可并行） |
| 3 | 设备端 + 服务器端 | 联调：下发 → 15 s 内送达 → 落盘 → 回执 | 1、2 |
| 4 | 宿主机（本项目） | `tools/publish` 加 `fetch` 子命令（端点不变） | 1 |
| 5 | 收尾 | 用 fetch 装 vanim 预置 JSON（首个真实用例） | 3、4 |

> 设备端与服务器端**可并行开发**：服务器端用 curl 自测信封；设备端用本地 mock（任一能开 HTTP 的机器）自测落盘。
