# 05 · 阶段路线与验收

> 配套阅读：01-目标与产品边界.md · 03-身份仓库与权限.md  
> 状态：调研建议，非排期承诺

---

## 1. 划分原则

1. **每阶段可独立交付价值**，可停在任意阶段。  
2. **工具能力不缩水**；阶段差异只在「谁能用哪些库、谁能管库」。  
3. **P0 优先「第二个真实用户跑通」**，而不是账号功能完备。  
4. 分享码、团队、开放注册都不在 P0 关键路径上。

---

## 2. 总览

| 阶段 | 名称 | 一句话 | 用户价值 | 主要工作 |
|---|---|---|---|---|
| **P0** | 让「另一个人」用起来 | 同款体验、零部署 | 伙伴能发布也能烧录 | 账号最小面、仓库归属、token 绑定 |
| **P1** | 项目可见性 | 私有/公开/授权 | 跨人用库、可控授权 | visibility、授权链接、下载收紧 |
| **P2** | 团队共管 | 成员与角色 | 一库多人发 | Membership、角色、审计 |
| **P3** | 开放服务 | 可对外收用户 | 规模化 | 注册策略、配额、域名证书、合规 |

---

## 3. P0 · 让「另一个人」用起来

### 3.1 目标

B（第二个开发者）在**不部署任何服务端**的前提下：

1. 拥有自己的固件仓库；  
2. 编译机 `tools/publish` 发布到自己的仓库；  
3. 打开工作站完成烧录、擦除、日志查看/导出；  
4. 能使用你**公开或已授权**的项目（可先只做公开）。

### 3.2 范围

**做：**

- 最小身份：邀请开号 / 魔法链接 / OAuth 三选一（见 03）  
- `User` + `Project.owner` 落库  
- publish token 绑定用户（可限项目）  
- registry 按 owner 隔离读写  
- 工作站侧栏区分「我的」与「公开」  
- 登录壳：进入 `/console` 需要登录；工作站可浏览公开库

**不做：**

- 分享码产品化  
- 团队成员  
- 计费、配额硬墙  
- 完整密码体系

### 3.3 验收（P0 DoD）

| # | 验收项 |
|---|---|
| P0-1 | 新用户注册/登录后得到空仓库与用户名下项目列表 |
| P0-2 | 用该用户的 publish token 发布成功，出现在其仓库 |
| P0-3 | 该用户在工作站完成连接→载入→烧录→日志导出 |
| P0-4 | 用户 A 无法写用户 B 的私有仓库（服务端 403） |
| P0-5 | 公开项目对另一用户只读可用（载入/下载/烧录） |
| P0-6 | 现有单用户自用链路不被破坏（回归烧录/日志/擦除） |
| P0-7 | `test` + `run build` 全绿；文档回写 |

### 3.4 工作量粗估

| 模块 | 规模 |
|---|---|
| 账号最小面 | M |
| 归属与鉴权中间件 | M |
| token 绑定与 CLI 兼容 | S |
| 前端库分组 + 登录壳 | S–M |
| 回归与真机清单 | S |

单人业余节奏 **1.5–3 周** 量级（不含开放注册）。

## 4. P1 · 项目可见性与授权

### 4.1 目标

- 项目 `visibility`: `private` / `public`（`internal` 可选）  
- 私有库可通过**授权链接/码**给指定人  
- 下载直链收紧（签名或带凭证）  
- 撤销授权立即失效

### 4.2 范围

**做：** Grant 模型、控制台发链/撤销、深链进工作站预载、SSE 按可见性过滤、页脚分享码找回（非主路径）。

**不做：** 团队角色细配、次数计费、水印溯源。

### 4.3 验收

| # | 验收项 |
|---|---|
| P1-1 | 私有项目未授权不可见、不可下载（服务端强制） |
| P1-2 | 授权链接打开后侧栏出现该库，工具能力完整 |
| P1-3 | 撤销后刷新即不可见 |
| P1-4 | 分享码可作深链失效时的找回入口 |
| P1-5 | SSE 不向未授权者推送私有项目事件 |

---

## 5. P2 · 团队共管

### 5.1 目标

同一仓库多人协作：owner / publisher / viewer。

### 5.2 范围

Membership、控制台成员页、角色对晋升/发链的约束、最小审计（发布人）。

### 5.3 验收

| # | 验收项 |
|---|---|
| P2-1 | 成员可在角色范围内发布/晋升 |
| P2-2 | viewer 不能发链、不能晋升 |
| P2-3 | 移除成员立即失去访问 |
| P2-4 | 发布记录带操作人 |

---

## 6. P3 · 开放服务

### 6.1 目标

可对外收陌生用户，具备基础防护与合规准备。

### 6.2 范围

公开注册策略、邮箱验证、限速/配额、垃圾账号治理、真实域名 + 受信证书、备份监控、用户协议/隐私政策、备案评估。

### 6.3 验收

| # | 验收项 |
|---|---|
| P3-1 | 注册→发布→他人下载全链路可用 |
| P3-2 | 滥用可限流/封禁 |
| P3-3 | 数据可备份恢复 |
| P3-4 | HTTPS 受信证书与域名就绪 |

---

## 7. 每阶段都要守住的红线

1. **esptool-js 只升不改**、分层纪律（`src/core` 零浏览器依赖）不变。  
2. **日志渲染纪律**不变。  
3. **密钥不入文档**。  
4. **工具能力清单**（01 章）不因权限系统裁剪。  
5. 鉴权在服务端强制。

## 9. 风险与应对

| 风险 | 等级 | 应对 |
|---|---|---|
| 账号/鉴权安全事故 | 高 | 不赶工；密钥隔离；越权测试进 CI |
| 多租户改坏单机自用 | 中 | 保留自用回退路径；回归清单 |
| registry 并发写 | 中 | 文件锁 + 乐观版本；发布单写者队列 |
| 下载直链外泄 | 高 | P1 收紧签名/短时 URL |
| 邮件送达失败（魔法链接） | 中 | 备选 OAuth；邀请码兑底 |
| 范围蔓延到 OTA/设备云 | 中 | 用 01 非目标清单挡 |

---

## 10. 建议的「下一步动作」（仍不动实现）

1. 你确认目标与阶段划分是否成立。  
2. 拍板 P0 登录形态（邀请 / 魔法链接 / OAuth）。  
3. 拍板仓库命名规则（`userId/slug` 还是全局 slug）。  
4. 再决定是否把 P0 作为正式迭代立项（那时才改代码）。
