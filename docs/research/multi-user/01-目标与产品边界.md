# 01 · 目标与产品边界

> 配套阅读：README.md（结论摘要）· 05-阶段路线与验收.md

---

## 1. 目标定义（定案表述）

> **托管的固件工作站**：别人不必自己部署，也能获得和你一样的完整体验——  
> **能发布、能下载、能烧录、能看日志、能擦除、能导出**。

### 1.1 拆开说

| 关键词 | 含义 | 不是 |
|---|---|---|
| 托管 | 平台集中部署，用户零运维 | 每人自建 Ubuntu + nginx |
| 固件工作站 | 浏览器内开发环境（现有 IDE 五区能力） | 网盘、下载站、OTA 控制台 |
| 和你一样 | 体验对等，工具能力全集 | 「下载访客」残血模式 |
| 发布 + 下载 | 每个用户都是完整用户 | 只有作者能发布、别人只能下 |

### 1.2 一句话门牌

**「别人开箱即用与我同款的发布/烧录/调试工作站。」**

---

## 2. 体验对等（产品原则）

多人化**不得**产生第二套「轻量 UI」。所有登录用户看到的是同一个工作站：

| 能力 | 单机时代（你） | 托管后（任何用户） |
|---|---|---|
| Web Serial 连接 / 芯片识别 | ✓ | ✓ 完全一致 |
| 烧录（参数注入、校验、重试） | ✓ | ✓ 完全一致 |
| 软件擦除 / 硬复位 | ✓ | ✓ 完全一致 |
| 日志监视 / 复制 / 导出 | ✓ | ✓ 完全一致 |
| 版本载入 / 打包下载 | ✓ | ✓ 完全一致 |
| SSE 订阅 NEW | ✓ | ✓ 按项目 |
| 固件库 | 自己一套 | **我的 / 被授权的 / 公开的** |
| 部署 | 自己维护 | **0**（平台托管） |

**唯一变化**：侧栏项目库的来源变多，以及可能出现管理入口。

---

## 3. 产品本体能力清单（不可因多人化裁剪）

面向开发者的便携调试环境：打开网页就是干活界面，不装驱动、不装 IDE 插件。

### 3.1 设备

- Web Serial 一键连接（ESP32-S3 原生 USB 优先）
- 芯片识别（MAC / Rev / Flash）
- 端口常驻、跨标签 Web Locks 互斥
- 拔线自动回收状态机

### 3.2 烧录

- 本地选 bin / 项目库一键载入
- 地址与烧录参数自动注入
- 进度、MD5 校验、失败降速重试
- 烧录前二次确认

### 3.3 擦除 / 复位

- 软件全片擦除（eraseFlash + 确认弹窗）
- 硬复位 / 烧录后自动复位
- 信号复位不断流（端口不关）
- 烧录临界区自动挂起/恢复日志

### 3.4 日志调试

- 开启监视即复位，抓全量启动日志（对齐 `idf.py monitor`）
- 行号终端、级别过滤、暂停视图
- 一键复制、导出 .txt
- 洪峰不卡页（批量渲染、seq key、显示上限）

### 3.5 固件库

- 项目 / 多芯片变体 / 版本时间线
- latest 载入、晋升、回滚、保留策略
- 分区类型标注（type/subType）
- 新发布 SSE 即时提醒（含轮询降级）

### 3.6 便携

- 纯浏览器，零安装
- 任意电脑打开即用
- 导出固件包（含 flash_args）可离线直烧
- Chrome / Edge 桌面为唯一支持目标

## 4. 非目标 / 明确不做（本期）

| 非目标 | 原因 |
|---|---|
| 下载访客残血模式 | 违反体验对等 |
| 分享码作为主产品形态 | 只是授权顺带工具 |
| 网盘式文件中转 | 产品是工作站不是存储 |
| 下载用户注册体系 | 不需要；进项目即用工具 |
| 计费 / 开放注册规模化 | 属于更后阶段（P3+） |
| 设备端 OTA / Improv / Home Assistant | 维持现有范围外 |
| Safari / iOS | 浏览器不支持 Web Serial |
| 读取备份固件、espefuse、espsecure | 维持现有范围外 |

## 5. 用户故事（目标态）

### 5.1 你自己（不变）

1. Windows + IDF 编译，`tools/publish --watch` 自动发布到**自己的仓库**。  
2. 任意电脑打开托管工作站，看到自己的项目库。  
3. 连接 S3，载入 latest，烧录，看日志，导出。

### 5.2 同事 / 伙伴 B（新增，体验对等）

1. 注册/登录一次（形式待定，见 03）。  
2. 得到自己的固件仓库；他的编译机用**他的** publish token 发布。  
3. 同一工作站：烧录自己的固件；也可以打开被授权的公开项目。  
4. **不需要部署任何服务端。**

### 5.3 跨人协作（P1+）

1. A 的私有项目想给 B 用 → A 发出授权（链接/邀请）。  
2. B 的侧栏出现该项目，载入烧录，与用自己的库无差别。  
3. 撤销授权后 B 不再可见。

## 6. 与现有 v1.5 的关系

**你今天用的体验 = 目标体验的单机版。** 已具备：

- publish CLI（once / --watch / 增量）
- registry（项目/变体/版本/时间线）
- 工作站全集（连接/烧录/擦除/日志/导出）
- SSE 订阅

多人化主要改的是**归属与权限**，不是重做工具。详见 [02-架构与站点结构.md](./02-架构与站点结构.md)。

---

## 7. 成功标准（方案层面）

1. 第二个用户零部署，完成「发布 → 另一端烧录 → 看日志」闭环。  
2. 该用户可使用的能力清单与你一致（无阉割模式）。  
3. 固件库归属清晰（我的 / 被授权的 / 公开的），越权访问被服务端拒绝。  
4. 工作站核心链路回归：烧录、擦除、日志导出在多人数据下仍可用。  
5. 自用模式可退化（单人私有部署仍可用），不被强制依赖公开注册。
