# USER-GUIDE — 使用手册（操作者视角）

> 本文面向**使用页面烧录设备、看日志**的同学，不涉及部署与代码。
> 部署运维见 `DEPLOY.md`；发布固件见 `PUBLISH.md`；故障排查见 `TROUBLESHOOTING.md`。

---

## 0. 环境要求

| 项 | 要求 |
|---|---|
| 浏览器 | **Chrome / Edge**（Web Serial 仅 Chromium 系支持；Firefox/Safari 不行） |
| 访问方式 | **HTTPS** 或 `localhost`（浏览器安全上下文限制；站点已是 HTTPS） |
| 数据线 | USB 线直连电脑（ESP32-S3 推荐接 **USB-Serial/JTAG 原生口**，勿接仅供电的 OTG 口） |
| 设备 | ESP32 系列；页面以 ESP32-S3 为第一优先目标 |

打开站点（示例：`https://firmware.example.com/`），自签证书首次提示信任一次即可。

## 1. 三分钟上手（最短路径）

```
① 点侧栏「▶ 连接设备」→ 浏览器弹出端口选择器 → 选中你的设备
   （授权只弹一次，以后连接免弹窗）
② 面板头点「▶ 开始监视」→ 设备自动复位，完整启动日志从 ESP-ROM 第一行开始刷
③ 侧栏「📁 项目库」点开项目 → 点某个版本 → 自动下载载入（或手动「添加 bin 文件…」）
④ 点「⚡ 烧录 N 段」→ 二次确认 → 等进度走完（烧录后自动硬复位）
⑤ 日志里看到新固件的启动输出 → 完成
```

## 3. 功能详解

### 3.1 设备（侧栏顶部）

| 操作 | 说明 |
|---|---|
| ▶ 连接设备 | 弹系统端口选择器（仅首次）；连接后自动识别芯片（型号/MAC/Flash/版本） |
| ⇄ 切换端口 | 换一块板子/换口 |
| ⏏ 断开设备 | 断开连接（端口授权保留，重连免弹窗） |
| 完全擦除 / 硬复位 | 快捷操作区；擦除有确认弹窗 |

**设备常驻连接**：连接一次后端口一直归页面管理；烧录/擦除时自动让出、结束后自动恢复，无需手动切换模式。

### 3.2 项目库（跨设备固件库）

- **📁 项目 / 变体文件夹**：点击折叠或展开版本列表（默认折叠）；徽标含义：`★发布`（绿底，正式版）、`快照`（灰，可被清理）、`●NEW`（红，远端有新发布）
- **点版本行** = 下载全部段并载入烧录表格（**地址和烧录参数自动注入**，面包屑可核对来源）
- **☆/★ 订阅**：订阅的项目有新发布时页面横幅提醒 + ●NEW 角标（SSE 即时推送，断线自动降级轮询）
- **版本时间线标签**：晋升（快照→发布版，必填说明）/ 回滚（latest 指向旧版本）/ 设置保留数（发布版永不自动删）

### 3.3 烧录

| 操作 | 说明 |
|---|---|
| ⚡ 烧录 N 段 | **二次确认**（芯片/段数/字节/地址清单）→ 挂起日志流 → 写入（MD5 校验）→ 自动硬复位 → 恢复日志 |
| 添加 bin 文件… | 手动多选；地址按文件名猜测（bootloader/partition/app），可手改 |
| ⬇ 导出固件包 | 当前清单 + `flash_args` + `README.txt` 打成 zip——可拷给没网的人用 esptool 离线烧 |
| 重新载入版本 | 重新按当前选中版本下载（怀疑文件过期时用） |

> ⚠ 写错固件可能无法启动——烧错后按住 **BOOT** 键进下载模式重新烧正确固件即可。

### 3.4 日志监视（核心能力，语义务必了解）

本页监视器**对齐 `idf.py monitor`**，三条语义：

1. **默认关闭，手动开启**：连接后不会自动占串口——点「▶ 开始监视」才开。好处：串口可让给本机 `idf.py monitor` 等外部工具（点「⏹ 停止监视」即让出）。
2. **开启即自动复位**：和 `idf.py monitor` 启动行为一致——点开监视后设备自动重启，**日志从 `ESP-ROM` 第一行开始**，完整启动过程一秒不缺。
3. **↻ 复位 = 信号复位，不断流**（等价 monitor 的 Ctrl+T Ctrl+R）：端口不关、日志不断、COM 不掉——看运行中设备随时重启抓新日志。

> **重要原理：串口无缓冲**。监视不在场时设备已经打印的输出**无法追回**。所以调试期建议：**先开监视再让它跑**；要重新看启动过程就点 ↻ 复位。

工具条：⏸ 暂停视图（日志照常收集，只是不滚动）｜级别过滤（全部/警告+/错误/设备）｜导出 .txt｜清空｜显示上限 500 条。

**底部面板四标签**：`问题`（警告+错误）/ `输出`（设备原始输出）/ `日志监视器`（全部）/ `烧录历史`。

### 3.5 操作卡：常见场景怎么用

**A. 抓全量启动日志**（验证开机流程）
```
连接 → ▶ 开始监视（设备自动复位）→ 从 ESP-ROM 刷起 → 全部拿到
想再看一遍：点 ↻ 复位（日志不断）
```

**B. 跑死 / 崩溃取证**（panic 现场）
```
▶ 开始监视（保持开着）→ 触发崩溃
→ Guru Meditation / assert / 看门狗 全文就在日志里（含堆栈）
事后才开监视是拿不到崩溃前输出的——务必监视先开
```

**C. 用本机 idf.py monitor**
```
页面点「⏹ 停止监视」（串口让出）→ 本机开 idf.py monitor
用完 → 页面点「▶ 开始监视」（会自动复位一次，重新从头抓）
```

**D. 烧录新固件并验证**
```
项目库点版本载入 → ⚡烧录（确认清单）→ 自动复位 → 日志直接看新固件启动
```

## 5. FAQ 速查

| 现象 | 处理 |
|---|---|
| 开了监视但没有设备输出 | 串口无缓冲 + 设备可能没在打印——点「↻ 复位」让它重新启动一遍 |
| 只看到一行 `ESP-ROM` 后静默 | 旧版本极性 bug，已修复；刷新页面（Ctrl+Shift+R）确保新版本 |
| 连接时报端口被占用 | 按四步排查：本标签已连？外部程序（monitor/串口助手）？另一浏览器？重插 USB ——详见 `TROUBLESHOOTING.md` §2 |
| 想抓崩溃现场但没抓到 | 崩溃时监视必须已在运行（见操作卡 B） |
| 浏览器要求 HTTPS | 用站点的 https:// 地址；或 localhost 部署（`DEPLOY.md` 快速路径） |
| 烧录后设备不启动 | 按住 BOOT 键重新上电进下载模式再烧；核对面包屑里的地址/参数 |

更多：`TROUBLESHOOTING.md`（日志无输出 / 401 / 增量发布 / SSE 不弹横幅 等）。
